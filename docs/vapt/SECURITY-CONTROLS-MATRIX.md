# C-DAC Feedback Portal: Security Controls & Compliance Matrix

| Requirement / Standard | Category | Implemented Mechanism | Verification Evidence |
|---|---|---|---|
| **CERT-In Direction 2(a)** | NTP Synchronization | Target servers are named (`docs/vapt/INCIDENT-RESPONSE.md` §4: `samay1.nplindia.org`, `samay2.nplindia.org`, `time.nic.in`) and `DEPLOYMENT-CHECKLIST.md` has an unchecked "NTP synced" deploy-time check. **No systemd-timesyncd/chrony config ships in this repo** — this is a Target, not an implemented control. | `docs/vapt/INCIDENT-RESPONSE.md` §4 (server names only, not a working config). |
| **CERT-In Direction 2(b)** | 6-Hour Incident Notification | Formal incident notification procedure to `incident@cert-in.org.in` with emergency contact workflow, plus a named "Security Incident Owner" placeholder for CDAC to fill in before go-live. | Documented in `docs/vapt/INCIDENT-RESPONSE.md`. |
| **CERT-In Direction 2(e)** | 180-Day Audit Logging | `public.audit_logs` is append-only, DB-enforced by trigger (`trg_audit_logs_no_change`/`trg_audit_logs_no_truncate` block UPDATE/DELETE/TRUNCATE for every role including the table owner). A controlled retention script (`server/src/db/retention-purge.ts`) is the one path allowed to age rows out past the 180-day floor (default 2 years), disabling/re-enabling the trigger inside one transaction. **Caveat:** log coverage is incomplete (authz failures, rate-limit/CORS blocks and bulk PII reads aren't audited yet) and this is append-only, not cryptographically tamper-evident (no hash chain, no off-host copy) — a Postgres superuser could still drop the trigger. | Verified in `server/src/db/migrations/002_security.sql:88-104` and `server/src/db/retention-purge.ts`. There is no `schema.sql` in this repo (migrations are `001-004_*.sql`); `server/src/routes/roster.ts` logs roster uploads but only a row count, not which fields changed. |
| **DPDP Act 2023** | Notice & Consent | **Target, not yet implemented as described.** The actual notice (`src/auth.tsx:99-148`) is a one-time, English-only `localStorage` flag per browser+email — no server record, no notice version, no withdrawal path, and staff get no notice at all. Its text also contradicts other parts of the system: it says "No third-party analytics or external CDNs" while Google OAuth and an optional WhatsApp share exist, and omits retention periods and the grievance/rights process. | `src/auth.tsx` (code, not this document's scope to fix) — see CMP-4. |
| **Core Privacy Invariant** | Student Anonymity | `public.responses` table contains only `id`, `session_id`, `answers` (JSONB) — no user email, PRN, IP, or timestamp column. $k \ge 3$ response threshold + randomized ordering, enforced in `submit_feedback()`/`session_report()`. **Caveat:** not linkage-proof at the raw storage layer — `responses` and `submissions` rows from the same submission share `xmin`/heap order, and `submissions.submitted_at` sits next to them, so a DB superuser or decrypted backup holder could still correlate by position/time (CMP-3, target to fix: write `responses` in a separate, randomly-delayed transaction). | Enforced in `submit_feedback` & `session_report` in `server/src/db/migrations/001_init.sql`. |
| **OWASP ASVS 2.1** | Session Management | Fastify signed cookies (`HttpOnly`, `SameSite=Lax`, `Secure`), 256-bit cryptographically random tokens, server-side revocation in `user_sessions`, and a live per-request roster re-check (`getSession` looks up the current role from the roster on every call — `server/src/auth/session.ts:45-59` — not a cached role, so removing someone from the roster revokes access on their very next request, no secret rotation needed). | Verified in `server/src/auth/session.ts` and `server/src/tests/server.test.ts`. |
| **OWASP ASVS 4.1** | Access Control (BOLA/IDOR) | PostgreSQL Row Level Security (RLS) policies using the `app.current_user_email` GUC (via `my_email()`) preventing horizontal cross-centre/cross-course data leakage. | Verified across all tables in `server/src/db/migrations/002_security.sql` and 11 tests in `server/src/tests/rls-app-role.test.ts` (vitest, not pgTAP — there is no pgTAP suite or `schema.sql` in this repo; the "47 pgTAP tests" figure in earlier drafts of this document was left over from the retired Supabase version of this project). |
| **OWASP ASVS 5.1** | Injection Defenses | 100% parameterised SQL queries (`$1, $2, ...`), Zod schema validation on all inputs, CSV formula sanitization (`=, +, -, @`). | Verified in route handlers and `aggregate.ts`. |
| **OWASP ASVS 14.4** | HTTP Security Headers | Strict CSP (`default-src 'self'`; `style-src` needs `'unsafe-inline'` for recharts/react-pdf), HSTS (`max-age=63072000; includeSubDomains` — **no `preload` on any nginx-sent header**; only Fastify's own Helmet config sets `preload: true`, visible on proxied `/api/*`/`/auth/*` responses only), `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`. `/healthz` and `/assets/*` intentionally send only HSTS + `nosniff` (CL-8, Low, not fixed in this pass). | Verified in `server/src/tests/server.test.ts` and `deploy/nginx/nginx.conf`. |
| **Zero CDN Policy** | Supply Chain Security | Zero external runtime CDN dependencies (`unpkg`, Google Fonts, `cdnjs`) — confirmed, no third-party requests on any route. **Correction:** there is no `@fontsource/inter` dependency and no bundled font files at all; `src/index.css` names `"Fira Sans"`, which the browser cannot find, so it silently falls back to the OS `system-ui` stack. Functionally harmless (no external request either way) but the stated mechanism was fictitious. | Verified by reading `package.json` and `index.html` (no font `<link>` or `@font-face`) and `src/index.css:9`. |
| **Data Resiliency** | Encrypted Disaster Recovery | Daily automated `pg_dump` with AES-256-CBC encryption (key via env var, never on argv), 180-day local retention pruning, and a restore drill script. **Residual risk** (INF-3, out of this document's scope to fix — see `docs/vapt/RESIDUAL-RISKS.md`): the dump runs as the Postgres superuser, and the offsite copy needs its SSH key mounted manually. | Implemented in `deploy/backup/backup.sh` and `deploy/backup/restore-test.sh`. |
